# 安全边界

Meerkit 是具有网络访问、数据库写入和本地子进程执行能力的管理服务。本页说明当前实现已经提供的保护，以及部署方必须承担的边界。

## 管理员认证

- 单管理员访问密钥至少 12 个字符。
- 密钥使用 Argon2id 哈希保存，不保存原文。
- 会话 Token 只以 SHA-256 摘要写入数据库。
- Cookie 为 HttpOnly、`SameSite=Lax`，直接 TLS 请求时带 `Secure`。
- GET 之外的管理请求需要 `X-CSRF-Token`。
- 会话默认 30 天，在剩余时间小于一半时滑动续期。
- 单进程内每个客户端 IP 在 10 分钟内最多 8 次失败登录。
- 修改或重置管理员密钥会撤销全部会话。

登录限速保存在内存中，重启后清空，也不跨实例共享。公网边界仍需要反向代理或防火墙限速。

## 传输安全

宿主目前不直接提供 TLS 配置。默认监听 `0.0.0.0:8080` 便于本地和容器使用，但不适合直接暴露到不可信网络。

生产部署应监听回环或私网，在反向代理上启用 HTTPS，并确保源站端口不可绕过。当前 Cookie 的 `Secure` 标记依据宿主看到的 TLS 状态；常见的 TLS 终止代理以 HTTP 回源时，宿主不会自动根据转发头补上该标记。因此必须保护回源网络、保持同站点访问，并在评估安全要求后决定是否对外提供服务。

## 数据与密钥

管理员哈希、会话、监控配置、通知配置和插件信任状态都在数据库中。当前通知配置中的 SMTP 密码、Webhook 头和其他敏感字段没有静态加密；`security.master_key_file` 尚未接入加密流程。

部署时应：

- 把数据目录权限限制给服务账户。
- 为 MySQL 使用最小权限账户和受保护的 DSN 注入方式。
- 避免把 DSN、通知密钥或管理员密钥写入命令历史和日志。
- 对数据库备份实施与生产数据库相同的访问控制。
- 定期轮换管理员密钥、SMTP 凭据、Webhook Token 和插件签名密钥。

配置元数据和主日志会遮蔽数据库 DSN 原文，但这不能替代数据库与配置文件权限。

## 插件执行边界

插件是本地子进程，不在容器、seccomp 或语言沙箱中。它继承宿主环境，并能以服务账户权限访问网络和文件系统。签名只证明包与某个 Ed25519 密钥关联且内容未被修改，不证明代码可信。

启用第三方插件前：

1. 从独立可信渠道核对公钥 SHA-256 指纹。
2. 阅读插件源码、许可证和运行前置条件。
3. 使用 `meerkit-plugincheck` 验证协议一致性。
4. 在隔离环境中观察网络、文件和进程行为。
5. 为服务账户和主机设置最小权限与网络出口规则。

解释器模式会从宿主 `PATH` 查找固定命令名，不使用 shell，也不展开变量或通配符。这降低了清单参数注入面，但解释器本身和插件代码仍拥有服务账户权限。

## 插件包防护

导入器拒绝路径穿越、绝对路径、符号链接、重复路径、过多文件、过大解压总量和异常压缩比。它还校验当前平台制品的大小和 SHA-256，并可校验签名信封。

发布私钥不应出现在仓库、应用主机或发布压缩包中。应用只需要公钥或签名信封中的公钥。

## 浏览器执行边界

Chrome 扩展拥有 `tabs`、`tabGroups`、`scripting`、`debugger` 和 `<all_urls>` 权限。成功配对的 Meerkit 可以让扩展在已选择标签页中读取 DOM、点击和填写控件、执行 JavaScript、截图并读取匹配的网络请求与响应正文。这相当于目标浏览器中的高权限自动化执行能力。

- 配对令牌由宿主随机生成，文件权限为 `0600`，但当前是本地静态秘密，不是用户级授权系统。
- 扩展 WebSocket 的第一帧使用令牌鉴权；后续依赖长连接，不使用管理员 Cookie。
- 令牌轮换会断开所有 Agent。怀疑泄露时应立即轮换，并更新每个可信扩展。
- 不要把浏览器 WebSocket 端点直接暴露到不可信网络；跨主机使用 `wss://`、网络访问控制和受保护的反向代理。
- 浏览器监控插件仍是本地可信代码。BrowserBridge 的插件身份隔离不能阻止恶意插件主动读取它被允许访问的浏览器内容。
- Chrome 登录态、页面正文、请求头和响应正文可能包含敏感数据。监控插件必须限制结果、正文大小和日志，避免持久化 Cookie、Authorization 或个人数据。

`runtime.evaluate` 会在页面主世界执行插件提供的表达式。扩展不允许管理前端维护任意工作流，但已启用的插件仍可组合原子能力，因此浏览器插件和普通监控插件应执行同等的信任审查。

### MCP 浏览器控制

`/mcp` 默认不注册。设置 `mcp.enabled=true` 后，该端点使用独立的静态 Bearer Token，Token 至少 32 个字符，并在配置元数据中遮蔽为 `configured`。MCP Token 与扩展配对令牌相互独立，轮换其中一个不会影响另一个。

MCP 获得的权限等同于浏览器调试页：可以读取页面与网络数据、操作标签页、填写表单、执行页面表达式并访问浏览器登录态。应使用密码管理器或密钥注入保存 Token，只授权给受信任的 AI 客户端，并限制端点的网络来源。公网或跨主机接入必须使用 HTTPS；怀疑泄露时立即替换 Token 并重启 Meerkit。

## API 暴露

`/healthz`、`/readyz`、认证初始化/登录、公共状态页和浏览器扩展 WebSocket 无需管理员会话。公共状态页使用分享 Token；扩展 WebSocket 使用配对令牌。启用后的 `/mcp` 使用独立 MCP Token。其余 `/api/v1` 管理路由要求会话。管理 API 目前没有通用 API Token、用户角色或细粒度权限系统。

如果需要多用户、审计隔离或外部自动化凭据，应在部署层增加访问代理，或者在项目中明确实现对应认证能力后再开放。
