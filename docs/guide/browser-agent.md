# 浏览器执行节点

Meerkit Browser Agent 是平台维护的通用 Chrome 执行端。它通过 Chrome 扩展 API 和 DevTools Protocol 执行标签页、DOM、脚本、截图与网络捕获操作，但不保存站点地址、采集步骤或结果解释。具体监控逻辑由监控插件维护。

## 加载扩展

当前扩展源码位于仓库根目录的 `browser-extension/`，开发验证时手动加载：

1. 打开 `chrome://extensions`。
2. 开启“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择 `browser-extension/`。
4. 打开 Meerkit 左侧“系统 > 浏览器”，复制 WebSocket 地址和配对令牌。
5. 打开扩展设置页，填写连接信息、节点名称与最大并发任务数并保存。

扩展会在 Chrome 本地存储连接设置和稳定的节点 ID，不会在浏览器启动时主动连接。首次填写配置后需要在设置页或 Popup 点击“连接后端”；成功建立连接后，主程序重启或网络中断时会自动恢复，首次连接失败或用户主动点击“断开连接”后需要再次手动连接。连接成功后，设置页会显示节点名称、扩展版本、能力列表和最近心跳。

::: tip 跨主机连接
WebSocket 地址必须是 Chrome 实际可访问的地址。本机开发通常使用 `ws://127.0.0.1:8080/api/v1/browser/extension/ws`；通过 HTTPS 反向代理访问时使用对应的 `wss://` 地址，并确保代理允许 WebSocket Upgrade。
:::

## 配对与令牌

Meerkit 首次启动时生成 32 字节随机配对令牌，保存在 `${storage.data_dir}/browser/pairing-token`。管理界面只在已登录的“浏览器”页面展示令牌。

扩展 WebSocket 不使用管理员会话 Cookie，而是在第一条 `hello` 消息中提交配对令牌。轮换令牌会立即断开所有已连接节点；每个扩展都必须保存新令牌才能重新连接。不要把令牌写入插件配置、监控结果、日志或公开文档。

## 浏览器工具

“浏览器工具”页面用于验证执行节点的原子能力，不是监控流程编辑器。顶部选择 Agent、窗口和标签页；桌面端左侧按分类显示可滚动的 Action 列表，中间显示 Catalog 驱动的参数，右侧显示结果预览、原始请求和原始响应。移动端会把左侧列表自动替换为 Action 下拉框。

目标规则分为三类：

| 目标模式 | 行为 |
| --- | --- |
| `none` | Action 不使用窗口或标签页 |
| `window_optional` | 可选择窗口；不选择时使用 Chrome 当前窗口 |
| `window_required` | 必须显式选择窗口 |
| `tab_required` | 必须显式选择标签页；同时提供窗口时校验归属 |

`tab.open` 属于 `window_optional`，窗口管理操作使用 `window_required`，页面、DOM、输入、Cookie、Storage 和脚本 Action 通常要求 `tab_id`。每个 Action 标题右侧都有固定位置的目标下拉，“无”表示使用顶部目标，选择具体标签页或窗口后则仅覆盖当前 Action 的执行目标。

当前提供：

- 窗口生命周期、标签页状态和导航历史。
- 页面信息、等待、滚动和 PNG/JPEG/WebP 截图。
- DOM 单项/多项查询、表单控件和滚动操作。
- CDP 真实鼠标、键盘和滚轮输入。
- Cookie、localStorage、sessionStorage 和 JavaScript 表达式。

完整的 56 项能力、参数默认值、范围和返回字段见[浏览器 Action 参考](/reference/browser-actions)。

Cookie 与 Storage 标记为敏感能力；调试页对读取操作直接显示结果，对写入、删除、清空及窗口/标签页关闭等破坏性操作要求二次确认。

`runtime.evaluate` 在页面主世界执行表达式，拥有目标页面上下文。只应在受控页面和可信表达式上使用。

完整页面截图可能产生较大的 Base64 结果。扩展会自动分块传输并处理发送背压；结果上限为 60 MiB。超长、图片密集页面优先选择 WebP 或 JPEG，并适当降低图片质量。超过上限只会让当前截图失败，不会主动断开执行节点。

## 网络捕获

网络捕获是独立会话，不是 Action。启动时必须选择标签页，并可设置 URL 包含文本、资源类型和正文大小上限。会话固定绑定启动时的标签页；之后切换顶部目标不会迁移捕获。

捕获通过 `chrome.debugger` 使用 CDP Network 域，返回请求方法、请求与响应头、正文、状态、协议、远端地址、缓存信息和时序。正文最大允许 1 MiB，超过配置上限时返回截断标记。

以下情况会停止会话并释放 debugger attachment：

- 用户点击停止捕获。
- 目标标签页关闭。
- 扩展与 Meerkit 的 WebSocket 断开。
- 发起捕获的监控插件停止、升级或异常退出。
- 插件未及时消费事件，导致该捕获的有界队列溢出。

## 与监控插件的关系

浏览器监控插件负责调用原子能力并生成 `Observation`。典型执行顺序为：

1. `tab.open` 创建标签页并保存返回的 `window_id/tab_id`。
2. 需要首次导航网络数据时，先在空白页启动捕获。
3. 后续 Action 显式携带目标 ID。
4. 达到条件或超时后停止捕获。
5. 插件解释采集结果并返回自己的结果集。
6. 关闭由本次执行创建的标签页。

扩展不提供标签页复用键，也不会在 Action 完成后隐式关闭标签页。标签页所有权和业务清理由调用插件负责。

## 常见问题

节点未显示时，依次检查扩展状态、WebSocket 地址、配对令牌、反向代理 Upgrade 和 Chrome 扩展后台日志。Action 返回目标归属错误时，刷新目标列表并重新选择标签页；Chrome 中移动或关闭标签页会让旧 ID 失效。

网络捕获无法启动通常表示同一标签页已被其他 DevTools/CDP 客户端占用，或扩展缺少 `debugger` 权限。更多检查项见[日志与排障](/operations/troubleshooting#浏览器执行节点)。实现边界见[浏览器自动化架构](/development/browser-automation)。
